# QEMU Static ELF Process Run

**Date:** 2026-11-03  
**Branch:** `work`  
**Host:** Darwin arm64  
**Emulator:** QEMU 11.1.3 (TCG)  
**Kernel:** x86-64 Limine image with the polling VirtIO block driver

The test image was generated by `make run` and contained `HELLO.ELF` in its
FAT32 root directory. The user program is a 179-byte static ELF64 executable
that writes `Eloquence is alive!` through the scalar console syscall and exits
with status 42.

## Observed results

- `fs list 0 1` displayed `HELLO.ELF` (179 bytes).
- `run 0 1 HELLO.ELF` printed `Eloquence is alive!` from ring 3.
- `run 0 1 HELLO.ELF` entered ring 3 and returned `Process exited with status 42.`
- Repeated runs returned status 42; a `run` attempt on the text file was rejected,
  and the next valid ELF still ran successfully.
- The existing boot-time EDU capability scenarios and timer remained active.

## Limits

This is a synchronous, single-process prototype. It accepts bounded static ELF64
executables only, has no scheduler or dynamic linker, and keeps its user
page-table hierarchy for reuse. Code and stack frames are reclaimed after each
run. Console output sends one validated ASCII character per syscall. The newer
`SHELL.ELF` fixture demonstrates non-blocking input; there is still no process
argument interface, and the syscall ABI remains experimental.
